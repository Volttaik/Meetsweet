# MeetSweet Backend — Full Developer Brief

**Mobile app:** Expo / React Native.
**All requests include header:** `X-Client-App-Id: meetsweet-mobile`
**All responses must be wrapped as:** `{ "ok": true, "data": { ... } }` or `{ "ok": false, "error": "...", "code": "..." }`

---

## SECTION 1 — CRITICAL: EXISTING ENDPOINTS SILENTLY DROPPING FIELDS

These routes exist and accept requests, but are not storing or returning required fields. This is breaking core features.

### POST /api/posts — Create Post

The endpoint accepts the request and returns an ID, but is ignoring these fields entirely:

- `content_type` — string, values: `"post"`, `"video"`, `"short"`, `"album"`. This is the most critical field. If it is not stored, shorts show up as videos everywhere, videos lose their label, and the entire content routing system breaks.
- `title` — string. Required for video posts. Currently vanishes after creation.
- `thumbnail_url` — string (URL). The custom thumbnail for a video. Currently ignored on save.
- `tier` — string, values: `"bronze"`, `"silver"`, `"gold"`, `"diamond"`. Subscription tier for the content.
- `tags` — array of strings.
- `categories` — array of category ID strings.
- `media_ids` — array of media record IDs linking uploaded media to the post.

All of these must be stored in the database and returned when the post is fetched. The response from `GET /api/posts/:id` and `GET /api/posts` must include all of them.

**Required response shape per post object (used everywhere posts are returned):**

```json
{
  "id": "string",
  "caption": "string",
  "title": "string | null",
  "content_type": "post | video | short | album",
  "visibility": "public | subscribers | draft",
  "tier": "bronze | silver | gold | diamond",
  "thumbnail_url": "string | null",
  "tags": ["string"],
  "categories": ["string"],
  "like_count": 0,
  "comment_count": 0,
  "save_count": 0,
  "liked_by_me": false,
  "bookmarked_by_me": false,
  "created_at": "ISO string",
  "published_at": "ISO string",
  "media": [
    {
      "id": "string",
      "url": "string",
      "type": "image | video",
      "thumbnail_url": "string | null",
      "duration_secs": null,
      "width": null,
      "height": null,
      "file_size": null
    }
  ],
  "creator_id": "string",
  "creator_display_name": "string",
  "creator_username": "string",
  "creator_avatar": "string | null",
  "creator_is_verified": false
}
```

## SECTION 2 — MISSING ENDPOINTS (ALL RETURN 404)

### A. Creator Content Feeds — HOME FEED IS COMPLETELY BROKEN WITHOUT THESE

The home feed is built by fetching posts from creators the user subscribes to, plus their own posts. Without these, the home feed is always empty.

- `GET /api/creators/:id/posts?limit=20&cursor=` — Posts by a specific creator. Same shape as post object above. Exclude drafts for non-owners.
- `GET /api/creators/:id/videos?limit=20&cursor=` — Only `content_type: "video"` posts from that creator.
- `GET /api/creators/:id/shorts?limit=20&cursor=` — Only `content_type: "short"` posts.
- `GET /api/creators/:id/albums?limit=20` — Only `content_type: "album"` posts.
- `GET /api/creators/:id` — Full public creator profile:

### B. Media Registration — UPLOADS SUCCEED BUT POSTS HAVE NO MEDIA WITHOUT THIS

The app uploads files directly to R2 storage via presigned URLs (which works). After upload it calls `POST /api/media` to register the file and get a media ID. That ID is then passed as `media_ids` when creating a post. Without this, no media ever attaches to any post.

- `POST /api/media` — Register an uploaded file.

  **Body:**
  ```json
  {
    "url": "string",
    "blob_path": "string",
    "type": "image | video",
    "mime_type": "string",
    "size_bytes": 0
  }
  ```
  **Response:** `{ "media": { "id": "string", "url": "string" } }`

- `PATCH /api/media/:id` — Update a media record (used to attach a thumbnail after upload).

  **Body:** `{ "thumbnail_url": "string" }`

## SECTION 3 — GLOBAL RULES (APPLY TO EVERY ROUTE)

1. **Every route must accept the header `X-Client-App-Id: meetsweet-mobile`.** Without it the app receives 403 and nothing works at all.
2. **All responses use the `{ "ok": true, "data": { ... } }` envelope** — no naked JSON objects.
3. **All response field names must be `snake_case`** (`avatar_url`, not `avatarUrl`; `like_count`, not `likeCount`).
4. **Auth-protected routes must return `401`** when the token is missing or expired — not 403.
5. **Idempotency:** Like, follow, bookmark, and subscribe actions must not create duplicate records if called twice. Re-liking something already liked should return 200, not an error.
6. **The `content_type` field is mandatory on every post object returned from every endpoint.** It must be stored on write and returned on read. This is the single most important fix.
